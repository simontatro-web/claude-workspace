> Summary: The ACT Math knowledge pack + templated item generator built for jarvis-1 (Sep 15 2026) — architecture, what is in the bundle, verification results, install path and known gaps. Read before extending Jarvis's ACT ability or debugging its generated items.

Companion to act-test-forms, act-distractor-patterns, jarvis-orchestrator, act-math-test-center-business.

- Jack (2026-09-15) wants Jarvis to have real knowledge of the ACT and to generate accurate ACT Math questions the way Claude does.
- his choices for the build: knowledge pack + templated generator + validator (not free-hand generation, not fine-tuning); Math only, deep; output to all three of chat, the Test Center artifact, and a printable booklet; minimal version usable this week (he tests Sat Sep 19).

ARCHITECTURE (the point of it): the local model computes NOTHING. Each question comes from a parameterized Python template that generates its own numbers, computes the key, derives each wrong choice from one named procedural error, then recomputes the key by a second independent route and refuses to emit the item if the two disagree. The model only chooses what to ask for and teaches from what comes back. Pure stdlib Python 3 — no numpy, no sympy — so it runs anywhere on jarvis-1.

BUNDLE jarvis-act-math/: knowledge/ (01-format, 02-item-design, 03-student-profile, 04-how-jarvis-should-use-this), gen/core.py (item model + build-time checks + registry), gen/t_number|algebra|functions|geometry|stats|ies.py (64 templates: N 10, A 10, F 11, G 15, S 9, IES 9), gen/assemble.py (drill or full 45-item form; writes .txt/.answers.txt/.json/.html booklet), gen/validate.py (independent auditor that re-reads the JSON without importing the templates), server/act_tools.py (FastAPI OpenAPI tool server, port 8103, four tools: generate_act_math, generate_act_form, act_knowledge, list_act_topics), seen_bank.json (no-repeat gate).

BUILD-TIME CHECKS per item: independent recomputation of the key; four choices distinct in VALUE as well as text (2√24 = 4√6 has shipped as a bug before); numeric choices sorted ascending; every distractor carries a one-sentence named error. FORM-level checks in validate.py: letters against item parity (A–D odd, F–J even), the 41-item scored blueprint N5 A7 F8 G8 S5 IES8, answer-position chi-square, stem length, context share.

VERIFICATION 2026-09-15 [MEASURED]: 5,120 generated items across all 64 templates — 0 check failures, 0 ordering failures, 0 duplicate-value failures. Two blind solve passes by a separate model (64 items each, no key available to it): agreement 64/64 and 64/64 = 100% key accuracy. The first blind pass also found 10 real item-quality defects, all fixed: a scientific-notation distractor numerically equal to the key (0.9×10⁻⁶ vs 9×10⁻⁷), ambiguous slope notation (−5/3x now written (−5/3)x), ambiguous √(x−a)/(x−b) (now [√(x−a)]/(x−b)), two transformation choices describing the same thing, "f(3+1)" and "3x + 0" generator artifacts, number-line choices out of ascending order, an impossible altitude distractor, "between X and Y, inclusive" wording. Second blind pass found only "1x"/"1π" coefficient artifacts and one ordering case — also fixed.

Delivered to Jack 2026-09-15 as jarvis-act-math.tar.gz (44 KB) plus a sample 45-item form and its answer key. Final sweep after all fixes: 5,120 items, 0 problems. assemble.py now also REBALANCES answer positions (re-draws items until chi-square <= 6); before that, seed 101 produced chi-square 9.31 and validate.py caught it.

FIGURES ADDED 2026-09-15 (batch 1), after Jarvis correctly refused to draw them itself: gen/figure.py renders self-contained SVG (no external fonts/scripts/images). 18 of 68 templates now carry a figure — right/general triangles, circle with inscribed angle, sector, cone, cylinder, rectangular solid, regular polygon, parallel lines + transversal, similar triangles, coordinate grid, number line, two-way table, bar chart. Four NEW figure-native templates: g_parallel_transversal, g_similar_triangles, f_read_line_graph, s_read_bar_chart. Two governing rules: (1) the drawing is computed from the item's own variables and Figure.verify() refuses any item whose printed number is not one the item computed (core.build takes figure= and fig_values=); (2) GEOMETRY figures are deliberately NOT to scale and say so, with an outline chosen off any common ratio and jittered per item so a 30-60-90 or 3-4-5 cannot be measured off the page, while grids/number lines/tables/charts ARE to scale (bar values forced onto gridlines) because reading them is the skill.

FIGURE VERIFICATION [MEASURED]: sweep 5,440 items / 0 problems. A blind agent was shown 18 RENDERED figures as images and solved them from the pictures alone: 18/18 agreement with the key. Its figure audit found 10 real defects, all fixed: radius-vs-diameter ambiguity (cone, cylinder), a clipped label, an arc_mark that swept the REFLEX side and named no angle (replaced with a quadratic through the bisector — this also fixed floating angle labels), a polygon label floating at the centroid, an extra radius drawn across a sector, a 30-60-90 drawn near enough to scale to measure (~32.6° vs 30°), an angle-sum figure drawn acute while its answer was obtuse (general_triangle now takes shape_angles and draws roughly-true angles with ±12% distortion), and a bar chart whose gridlines fell between the bar values. Figure coverage is 10–12 of 45 per form vs the official 16–18: STILL MISSING nets/cross-sections, piecewise distance-time graphs, scatterplots with a line of best fit, chord/tangent circle items, vertical-angle diagrams — that is batch 2.

KNOWN GAPS (honest): answer position still runs light on the last choice (D/J) because ascending numeric choices plus "too big" distractors park the key mid-list — chi-square lands ~5 vs the 7.81 threshold; stem median 22 words vs the official 36 — items read terser than real ones; NO FIGURES yet, while official forms reference a figure on 16–18 of 45 items, so Geometry is stated in prose; band mix comes out ~10 easy/19 mid/12 hard vs the 8/25/12 target because of which templates exist at which difficulty; the .json uses this project's own clean schema, NOT the Test Center artifact's test.json schema — an adapter still needs writing and needs the Test Center's schema (or the act-tests-bundle-v2.tar.gz toolchain) to write against.

INSTALLED ON JARVIS-1 2026-09-15 by Jarvis itself via run_host_command, all checks reproduced on the box [MEASURED]: 64 templates, sweep 5,120 items / 0 problems, seed-1 form blueprint A7 F8 G8 IES8 N5 S5, chi-square 1.13, 45/45 arithmetic-checked, validate.py "0 errors". Two install facts worth keeping: (1) an Open WebUI chat attachment lands INSIDE the container at /app/backend/data/uploads/\<uuid>_\<name> and must be pulled out with docker cp open-webui:... ~/, it is not on the host filesystem; (2) jarvis-1's Python 3.12 is PEP 668 externally-managed, so pip install --user is refused — Jarvis correctly built a venv at ~/venvs/act-tools instead of using --break-system-packages. Service runs as ~/venvs/act-tools/bin/python ~/jarvis-act-math/server/act_tools.py; systemd unit jarvis-act-tools.service drafted (needs root to install).

BUG FOUND AND FIXED 2026-09-15 AFTER INSTALL: act_tools.py bound 127.0.0.1, which Open WebUI's container CANNOT reach — host.docker.internal resolves to the host's bridge address, not its loopback, so the tools would have silently failed to connect. Jarvis asserted the route "works" without testing from inside the container. Fixed: the server now binds 0.0.0.0 by default, overridable with ACT_TOOLS_HOST. The test that settles it either way: docker exec open-webui curl -s -m 5 http://host.docker.internal:8103/list_act_topics.
