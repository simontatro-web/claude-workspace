## GLM-5.3 QUANT QUALITY TABLE (real numbers, from Unsloth's own docs, pulled Sep 22 2026)

Jack asked what the quality tradeoff from 3-bit to 4-bit actually is. Unsloth publishes a benchmark table for unsloth/GLM-5.3-GGUF (top-1 token accuracy vs full precision, mean KLD, perplexity): | Quant | Size (GB) | Top-1 accuracy | Mean KLD | Perplexity | | UD-IQ1_S | 216.7 | 72.56% | 0.688 | 4.613 | | UD-IQ1_M | 228.5 | 75.64% | 0.565 | 4.141 | | UD-IQ2_M | 238.6 | 78.53% | 0.454 | 3.743 | | UD-Q2_K_XL | 253.9 | 80.93% | 0.374 | 3.505 | | UD-IQ3_XXS | 281.7 | 84.15% | 0.273 | 3.248 | | UD-Q4_K_XL | 467.3 | 94.29% | 0.037 | 2.701 | | UD-Q5_K_XL | 562.5 | 95.82% | 0.020 | 2.684 | No UD-Q3_K_XL row exists in this benchmark table (it exists as a downloadable file, 343GB/319GiB per the HF tree API pulled Sep 21, per local-model-landscape, but Unsloth didn't benchmark it) — UD-IQ3_XXS (281.7GB/~262 GiB) is the nearest actually-benchmarked ~3-bit-class point. The real gap, 3-bit-class to 4-bit: top-1 accuracy 84.15% -> 94.29% (10 points), mean KLD 0.273 -> 0.037 (~7.4x worse divergence from full-precision output at 3-bit), perplexity 3.248 -> 2.701 (+20%). Unsloth's own stated recommendation: "Q4_K_XL and Q5_K_XL are very close to baseline, so aim for those" — i.e. their own bar for "close to lossless" starts at Q4, not Q3. Tension with this: Q4_K_XL (435 GiB) barely fits Jack's ~450 GiB estimated-available RAM (15-65 GiB headroom, swap-hazard territory per local-model-landscape's Sep 22 fit-verdict note), while UD-IQ3_XXS (262 GiB) leaves ~185+ GiB of comfortable headroom. This is a genuine quality-vs-headroom tradeoff, not a free upgrade either direction.

## DOES ANY OTHER RUNNABLE MODEL BEAT GLM-5.3 (FULL) IN PRACTICE?

Full-precision Artificial Analysis Intelligence Index scores on file (from cpu-moe-speed-levers's survey): MiMo-V2.6-Pro 46 > GLM-5.3 (full) 45 > GLM-5.3-Flash 42; Hy4-preview isn't on that index but vendor head-to-heads put it as a close peer to GLM-5.3-Flash (mean delta near zero excluding one outlier benchmark) and Tencent's own blind eval has Hy4 edging the FULL GLM-5.3 46.8% wins to 40.4% losses among their own engineers. None of that full-precision ranking is deliverable on Jack's box today:

- MiMo-V2.6-Pro (highest score): still no GGUF exists for V2.6 at all — not a real option yet regardless of quant.
- GLM-5.3-Flash (42, below GLM-5.3 full): architecture still unmerged (3 open PRs) — not runnable on stock llama.cpp.
- Hy4-preview: IS runnable (architecture merged), and full-precision it may be a close peer to GLM-5.3 full. But no quant-quality table (KLD/perplexity/top-1) was found for Hy4-preview's GGUFs, unlike GLM-5.3's detailed table above — the only quant-loss numbers on file for Hy4 are AngelSlim's own [VENDOR] claim of "~1% loss" going to MIX-STQ1_0 (~1-bit), which doesn't cover the UD-IQ1_M file Jack could actually run (2.44 bpw) or let him compare against GLM-5.3's Q3/Q4-class numbers. Hy4's only runnable-size quant (UD-IQ1_M, 2.44 bpw) is also a much more aggressive squeeze than GLM-5.3's 3-4 bit options, and lower bpw reliably means more quality loss — so even if Hy4 and GLM-5.3 are close at full precision, Hy4 is very likely being hurt MORE by quantization at the sizes Jack would actually run it at, per the same bits-per-weight-vs-accuracy relationship the GLM-5.3 table shows directly. CONCLUSION: no other model confirmed to beat GLM-5.3 (full) in what Jack could actually run and measure today. MiMo-V2.6-Pro and GLM-5.3-Flash are blocked outright (no GGUF / no merged architecture). Hy4-preview is runnable but its accuracy-at-the-quant-Jack-would-use is unmeasured, and the bits-per-weight math suggests it's disadvantaged relative to GLM-5.3 at Q3/Q4. Re-open this if Hy4 gets a proper KLD/perplexity table published, or when MiMo-V2.6-Pro gets a GGUF.

Sources: unsloth.ai/docs/models/glm-5.3 (GLM-5.3 quant benchmark table); gguf-bench.com (general MoE-vs-dense quant resilience claim: "MoE models... dramatically more resilient across the quant range" — a generic claim, not GLM-specific numbers, and GLM-5.3's own table above still shows a real 10-point/7.4x-KLD gap at 3-bit despite being MoE); huggingface.co/unsloth/GLM-5.2-GGUF discussion #3 (checked, no usable numeric table extracted, only rough "76.2% at 1-bit / 82% at 2-bit / Q4-Q5 lossless" claims for the prior-generation model).
